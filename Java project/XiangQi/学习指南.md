## 2. Java 语言基础

### 2.1 程序如何运行

需要分清：

- **JDK**：开发工具包，包含编译器和运行环境。
- **JRE / JVM**：JVM 执行 `.class` 字节码。
- `javac Foo.java`：编译成 `Foo.class`。
- `java Foo`：运行类中的 `main(String[] args)`。
- **classpath**：JVM 去哪里找类文件；命令行用 `-cp`，IDE 自动处理。
- **package**：包名对应目录结构；本项目根包是 `edu.sustech.xiangqi`。
- **入口**：`public static void main(String[] args)`。

Swing 程序需要从事件分派线程（EDT）启动：

```java
SwingUtilities.invokeLater(Main::startApplication);
```

**要会回答**：为什么 Java 能跨平台？字节码和 JVM 的关系是什么？`javac` 与 `java` 分别做什么？

### 2.2 基础语法与数组

必须熟练：

- 基本类型：`int`、`boolean`、`char`、`double`，以及包装类型 `Integer` 等。
- 运算符：算术、比较、逻辑、位运算（本 Demo 主要用前三种）。
- 控制流：`if/else`、`switch`、`for`、`while`、`break/continue`。
- 方法：参数、返回值、重载、递归（进阶 AI 会用到）。
- 作用域：局部变量、字段、`static`、`final`。
- 数组：一维、二维、默认值、越界异常 `ArrayIndexOutOfBoundsException`。

**二维数组是棋盘的基础。** `Board` 中：

```java
private final Piece[][] pieces = new Piece[ROWS][COLS];
```

- `pieces[row][col]` 存棋子或 `null`。
- 行 0 在上方（黑方），行 9 在下方（红方）；列 0~8 从左到右。
- 棋盘本身不保存“每个棋子的坐标”，坐标由数组下标隐含，避免两份数据不一致。

需要掌握 `Math.abs`、`Math.round`、`Integer.signum` 等常用工具方法：

- `Math.abs(toRow - fromRow)`：判断距离。
- `Math.signum(...)`：得到 -1/0/1，用于沿路径逐格检查。
- `Math.round(...)`：把屏幕像素坐标四舍五入到最近交叉点。

### 2.3 面向对象

这是项目最核心的 Java 知识。

| 概念 | 在本项目中的体现 |
|---|---|
| 封装 | `Board.pieces` 是 `private`，外部只能通过 `getPieceAt` / `tryMove` 操作 |
| 继承 | `GeneralPiece`、`AdvisorPiece` 等继承 `Piece` |
| 抽象类 | `Piece` 定义抽象方法 `canMove(...)`，不能直接实例化 |
| 多态 | `Piece piece = board.getPieceAt(...)`，实际调用对应子类的 `canMove` |
| 接口 | `MouseAdapter` 是类；事件监听器本质实现接口（如 `ActionListener`） |
| 组合 | `ChessFrame` 持有 `Board`、`BoardPanel`、`SaveManager` |
| 枚举 | `PieceType` 限定七种棋子；`GameStatus` 限定四种状态 |
| 不可变对象 | `Position`、`Move` 的字段都是 `final` |
| 工厂 | `PieceFactory.create(type, red)` 集中创建棋子 |

**为什么棋子用抽象类？**

七种棋子都有“类型、红黑、名称”，但走法不同。抽象父类统一身份和接口，子类只实现 `canMove`。`Board` 不需要知道具体是“马”还是“车”，直接调用 `piece.canMove(...)`，这就是多态。

**为什么把规则放在模型而不是界面？**

如果界面里写“马怎么走”，换界面（Swing → JavaFX）就要重写规则，而且测试困难。模型只依赖 Java 标准库，可以单独编译和测试。

**为什么要有 `Position` 而不是到处传两个 `int`？**

- 可读性：`new Position(row, col)` 比 `int row, int col` 成对传递更清楚。
- 可以放进 `List<Position>`，并用 `equals/hashCode` 判断相等。
- 不可变，避免被别的代码修改。

**为什么 `Move` 记录的是 `PieceType` 而不是 `Piece` 对象？**

存档要能保存和重建着法；用类型 + 颜色 + 坐标就能完整复原显示信息，也不必担心对象引用。

### 2.4 常用类与集合

必须会：

- `String`：不可变；比较内容用 `equals`，不要用 `==`。
- `StringBuilder`：频繁拼接时比 `+` 更合适；存档生成、着法记录使用。
- `String.format`：格式化编号，例如 `String.format("%2d. ", i + 1)`。
- `char` 与 `Character.isUpperCase`：存档里用大小写表示红黑方。
- `List` / `ArrayList`：着法历史、合法落点。
- `Collections.unmodifiableList`：对外暴露只读视图，防止外部修改内部列表。
- `List.copyOf`：复制列表用于快照。
- `Map` / `LinkedHashMap`：`UserStore` 保存用户名到用户的映射，并保持插入顺序。
- `Objects.requireNonNull` / `Objects.equals` / `Objects.hash`。
- `Locale.ROOT`：用户名转小写时避免依赖系统语言环境。
- `Arrays.fill`、`Arrays.equals`：清空密码字符数组、比较两次密码。
- 泛型：`List<Move>`、`Map<String, User>`；理解类型擦除即可，基础用法更重要。

集合使用的注意事项：

- 遍历集合时不要随意增删（会 `ConcurrentModificationException`）。
- `List.of()` 创建不可变列表；需要添加元素时用 `new ArrayList<>()`。
- `Collections.unmodifiableList(list)` 是视图，不复制；原列表变化，视图也变化。
- 返回内部列表前先包装成只读，能减少误改。

### 2.5 异常处理

必须区分：

- **受检异常（checked）**：必须捕获或声明，如 `IOException`、`InvalidSaveException`。
- **非受检异常（unchecked）**：如 `NullPointerException`、`IllegalArgumentException`、`NumberFormatException`。

关键写法：

```java
try {
    // 可能失败的 I/O
} catch (IOException exception) {
    // 给用户看的提示
} finally {
    // 一定要执行的清理
}
```

读取文件使用 try-with-resources，自动关闭：

```java
try (BufferedReader reader = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
    // 逐行读取
}
```

本项目的异常策略：

- 模型层尽量不弹窗、不打印，只返回布尔值或抛异常。
- 存储层用 `IOException` 表示读写失败，用 `InvalidSaveException` 表示存档格式/内容非法。
- 界面层统一 `catch`，转换成 `JOptionPane` 提示，保证程序不崩溃。
- `SaveManager.loadInto` 先解析并校验完整存档，最后才修改棋盘；中途失败不会破坏当前对局。
- `Board.wouldKeepGeneralSafe` 用 `try/finally` 保证模拟移动后一定回滚棋盘。

**常见错误**：只写 `catch (Exception e) {}` 把问题吞掉。可以捕获，但日志/提示/返回值必须让问题可见。

### 2.6 现代 Java 特性（可加分）

本项目用到了：

- **Lambda**：`event -> saveGame()`、`this::refreshView`。
- **方法引用**：`Main::startApplication`。
- **switch 表达式**：`PieceFactory.create`、`resultText`。
- **文本块**：`ChessFrame.showRules` 中的 `"""..."""`。
- **pattern matching for instanceof**：`Position.equals` 中的 `other instanceof Position position`。
- **var**：测试里 `var stream = Files.walk(path)`。

了解即可（进阶可用）：

- `record`：适合替代简单不可变类，例如 `record Position(int row, int col) {}`。
- `Stream`：过滤、映射、收集；项目规模小，不必强行使用。
- `Optional`：表达“可能没有值”，但模型里返回 `null` 也完全可接受；关键是统一约定。

## 3. 架构设计：MVC 与数据流

### 3.1 分层

```
┌────────────────────────────────────────────────────────────┐
│ view（界面）                                                │
│  LoginDialog   BoardPanel   ChessFrame                     │
│  只负责显示、收集用户输入、弹提示                            │
└───────────────▲──────────────────────────┬─────────────────┘
                │ refreshView()            │ 点击/按钮事件
┌───────────────┴──────────┬───────────────▼─────────────────┐
│ controller（交互）        │ storage（持久化）                │
│  ChessController         │  AuthService / SaveManager       │
│  把鼠标点击转为选中/走子   │  注册登录、存档读写              │
└───────────────┬──────────┴───────────────┬─────────────────┘
                │                            │
┌───────────────▼────────────────────────────▼────────────────┐
│ model（规则与数据，不依赖 Swing）                           │
│  Board  Piece(+7 子类)  Move  Position  GameSnapshot        │
└────────────────────────────────────────────────────────────┘
```

### 3.2 一次点击的完整流程

1. 用户点击棋盘。
2. `ChessController.mouseClicked` 收到 `MouseEvent`。
3. `BoardPanel.getIntersectionAt` 把像素坐标转换为 `(row, col)`。
4. 控制器判断是“选中”“换选”还是“尝试移动”。
5. 移动时调用 `Board.tryMove(...)`。
6. `Board` 检查回合、己方目标、棋子局部规则、模拟后是否安全。
7. 成功则修改数组、追加 `Move`、换边、判断将军/将死/困毙。
8. 控制器调用 `onBoardChanged.run()` → `ChessFrame.refreshView()`。
9. 界面更新标签、历史记录、按钮状态，并 `repaint()` 棋盘。

**单向数据流**：界面不直接改棋盘数组；规则不直接改界面。这样调试时可以只盯 `Board`。

### 3.3 关键设计选择

| 问题 | 选择 | 好处 |
|---|---|---|
| 棋盘怎么表示 | 10×9 的 `Piece[][]` | 坐标即下标，简单直观 |
| 走法规则放哪 | 每种棋子 `canMove` + `Board` 全局检查 | 局部规则与全局规则分离 |
| 如何判断送将 | 临时移动、检查、回滚 | 复用现有规则，逻辑不易漏 |
| 如何判断无子可走 | 枚举所有棋子所有落点，逐个 `isLegalMove` | 简单可靠，性能足够 10×9 棋盘 |
| 如何读档不破坏当前局 | 先解析校验，最后 `restore` | 失败时当前对局不受影响 |
| 如何保存历史 | `List<Move>` + 存档中逐条记录 | 界面显示、读档恢复都方便 |
| 如何只让用户读自己的档 | 账号名参与文件路径 + 登录身份来自密码验证 | 简单且满足基本隔离要求 |

## 4. 中国象棋规则速查

### 4.1 棋盘与坐标

- 9 列 × 10 行交叉点，棋子放在交叉点上。
- 中间是“楚河汉界”；红方在下方，黑方在上方。
- 双方九宫：3 列 × 3 行。
  - 黑方：行 0–2，列 3–5。
  - 红方：行 7–9，列 3–5。
- 本 Demo 坐标：`(行,列)`，左上角 `(0,0)`，红方底线为第 9 行。

初始局面（大写红方，小写黑方，`.` 为空）：

```

行1   . . . . . . . . .
行2   . c . . . . . c .
行3   s . s . s . s . s
行4   . . . . . . . . .
        楚 河   汉 界
行5   . . . . . . . . .
行6   S . S . S . S . S
行7   . C . . . . . C .
行8   . . . . . . . . .
行9   R H E A G A E H R
```

|---|---|---|---:|

| A/a | 仕 | 士 | 2 |

### 4.2 七种棋子的走法

| 棋子 | 走法 | 关键限制 | 易错点 |
|---|---|---|---|
| 帅/将 | 九宫内沿直线走一格 | 不能出九宫；两将不能照面 | 斜走非法；跑出九宫非法；飞将规则 |
| 仕/士 | 九宫内斜走一格 | 只能走九宫的 5 个斜线点 | 直走非法；走出九宫非法 |
| 相/象 | 走“田”字（斜两格） | 不能过河；“象眼”不能有子 | 只检查终点不检查象眼 |
| 马 | 走“日”字（2+1） | “马腿”不能有子 | 马腿方向判断错误 |
| 车 | 同行/同列任意格 | 路径上不能有子 | 忘记检查中间路径 |
| 炮 | 同行/同列 | 不吃子：路径全空；吃子：恰好一个炮架 | 吃子时仍按“路径全空”判断 |
| 兵/卒 | 未过河只能前进一格；过河后可前进或左右一格 | 永远不能后退、不能斜走 | 过河判断用起点行号；横走限制 |

具体补充：

- **帅/将的飞将**：若两将同列且中间没有任何棋子，是非法局面；规则也允许将沿空列直接吃对方将。Demo 两者都实现了：`Board.isGeneralSafe` 阻止走出照面局面，`GeneralPiece.canMove` 支持飞将吃将。
- **象眼**：起点和终点的正中间交叉点，例如 `(9,2) → (7,0)` 的象眼是 `(8,1)`。
- **马腿**：先沿两格方向直走的那一格。`dr=2` 时马腿在起点上下方一格；`dc=2` 时马腿在起点左右方一格。
- **炮架**：起点与终点之间的棋子数量，不包含起点和终点的棋子。吃子必须有且只有一个；不吃子必须为零。
- **过河**：红兵从第 6 行出发，到达第 4 行及以下算已过河；黑卒从第 3 行出发，到达第 5 行及以上算已过河。横向移动的判断应看“当前所在行”，不是目标行。

### 4.3 回合、吃子、将军、胜负

1. 红方先行，双方轮流，每次恰好走一子，不允许停着。
2. 可以走到对方棋子所在点完成吃子；不能落在己方棋子上，不能出棋盘。
3. 走完后不能让己方将帅处于被攻击状态（不能送将），也不能形成两将照面。
4. 被将军时必须应将：移开将帅、吃掉攻击棋子、或用其他棋子挡住攻击线。
5. 一方没有任何合法走法即判负：
   - 若当前被将军 → **将死**（checkmate）。
   - 若当前未被将军 → **困毙**（stalemate，本项目按规则判负，不是和棋）。
6. 认输的一方输；双方同意可以判和棋。
7. Demo 还支持直接吃掉将帅（正常对局不会出现，但规则上可以结束）。

### 4.4 合法走法的完整判断顺序

```
输入：起点 (fr,fc)、终点 (tr,tc)
1. 坐标在棋盘内？                        否 → 非法
2. 起点与终点不同？                       否 → 非法
3. 起点有棋子？                           否 → 非法
4. 终点不是己方棋子？                     否 → 非法
5. 棋子的局部规则 canMove 通过？          否 → 非法
6. 临时移动后，己方将帅安全？             否 → 非法
   - 没有被对方任何棋子攻击
   - 两将没有同列照面
7. 合法；若是 tryMove，还要检查：
   - 当前是否轮到此方
   - 对局是否还在进行
```

第 6 步是关键。`Board.isLegalMove` 只做 1–6 步，方便“判断某一方是否还有棋可走”；`Board.tryMove` 在此基础上增加回合和终局检查，并真正修改棋盘。

### 4.5 传统中文记谱（进阶了解）

正式记谱如“炮二平五”“马8进7”，需要根据红黑方视角、列编号、前进/后退和同列棋子情况生成，比坐标记法复杂。基础 Demo 用 `(行,列)` 更直观；如果要做“导出棋谱”进阶功能，可以参考传统记谱规则，但不属于基础分要求。

## 5. 规则实现算法详解

### 5.1 棋盘与屏幕坐标

`BoardPanel` 中：

```java
screenX(col) = MARGIN + col * CELL_SIZE
screenY(row) = MARGIN + row * CELL_SIZE
```

鼠标坐标转棋盘坐标：

```java
col = round((x - MARGIN) / CELL_SIZE)
row = round((y - MARGIN) / CELL_SIZE)
```

再用圆形命中范围（`dx² + dy² ≤ HIT_RADIUS²`）过滤掉离交叉点太远的点击。

需要掌握：屏幕坐标 y 轴向下增长；棋盘行号也向下增长；不要混淆行/列与 x/y。

### 5.2 每类棋子的实现要点

`canMove` 只回答“这个棋子能不能这样走”：

```java
public abstract boolean canMove(Board board, int fromRow, int fromCol,
                                int toRow, int toCol);
```

- **GeneralPiece**
  - `abs(dr) + abs(dc) == 1` 且在九宫。
  - 飞将：同列、目标是对方将帅、路径中间无子。
- **AdvisorPiece**
  - `abs(dr) == 1 && abs(dc) == 1` 且在九宫。
- **ElephantPiece**
  - `abs(dr) == 2 && abs(dc) == 2`。
  - 象眼 `((fr+tr)/2, (fc+tc)/2)` 为空。
  - 红方 `toRow >= 5`，黑方 `toRow <= 4`。
- **HorsePiece**
  - `(abs(dr), abs(dc))` 为 `(2,1)` 或 `(1,2)`。
  - 计算马腿并检查为空。
- **RookPiece**
  - 同行或同列。
  - `isPathClear` 检查中间。
- **CannonPiece**
  - 同行或同列。
  - `countPiecesBetween`。
  - 目标是空位 → 数量必须为 0；目标是棋子 → 数量必须为 1。
- **SoldierPiece**
  - 前进一步：红 `row-1`，黑 `row+1`。
  - 已过河且 `toRow == fromRow && abs(dc) == 1` 可横走。
  - 不允许后退。

### 5.3 将军检测

`Board.isGeneralSafe(red)`：

1. 找到本方将帅；找不到 → 不安全。
2. 找到对方将帅；若同列且中间无子 → 不安全（照面）。
3. 遍历对方所有棋子，调用它们的 `canMove` 指向本方将帅；任意一个返回 `true` → 不安全。
4. 否则安全。

`isInCheck(red)` 就是 `!isGeneralSafe(red)`。

注意：检测攻击时只看“几何上能不能走到将帅”，不检查攻击方自己是否会被将军。对将帅安全判断来说这是合适且常见的做法；它也让“将帅不能照面”和“不能送将”统一处理。

### 5.4 模拟-回滚

```java
Piece captured = pieces[toRow][toCol];
pieces[fromRow][fromCol] = null;
pieces[toRow][toCol] = piece;

boolean safe;
try {
    safe = isGeneralSafe(piece.isRed());
} finally {
    pieces[toRow][toCol] = captured;
    pieces[fromRow][fromCol] = piece;
}
return safe;
```

这是整个项目最值得掌握的技术：

- 不需要为每种棋子单独写“走完后会不会被将军”的判断。
- 复用 `isGeneralSafe`，自动处理挡将、吃攻击子、飞将。
- `finally` 保证即使检查过程抛异常也恢复棋盘，避免状态污染。

### 5.5 将死与困毙

走完一步后：

```java
redToMove = !redToMove;
if (!hasAnyLegalMove(redToMove)) {
    status = redToMove ? BLACK_WIN : RED_WIN;
    endReason = isInCheck(redToMove) ? "将死" : "困毙（无子可走）";
}
```

`hasAnyLegalMove(red)` 枚举该方每个棋子的每个落点，调用 `isLegalMove`。只要找到一个合法走法就返回 `true`。

性能评估：90 个格子 × 最多 16 个棋子 × 每步模拟检查约 90 个格子，约十几万次基本操作，Swing 中完全可接受。真正需要性能优化的是 AI 搜索，而不是基础规则。

### 5.6 边界条件清单

实现和测试时逐条检查：

- [ ] 黑方第一步不能走（红先）。
- [ ] 不能连续走两步。
- [ ] 不能吃己方棋子。
- [ ] 不能原地不动。
- [ ] 不能走出棋盘。
- [ ] 马腿、象眼、炮架的阻挡。
- [ ] 象不能过河。
- [ ] 兵过河前不能横走，过河后不能后退。
- [ ] 将是九宫内直走一步，不能斜走。
- [ ] 两将照面非法。
- [ ] 走完后己方将帅不能处于被攻击状态（不能送将）。
- [ ] 被将军时只能走应将的棋。
- [ ] 将死与困毙都判负，但提示文字不同。
- [ ] 认输、和棋后不能继续走棋。
- [ ] 吃子后历史记录包含被吃棋子。
- [ ] 上一步从/到位置可被界面获取并显示。

| 类 | 用途 | 本项目位置 |
|---|---|---|
| `JFrame` | 主窗口 | `ChessFrame` |
| `JDialog` | 模态对话框 | `LoginDialog` |
| `JPanel` | 容器/自定义绘制面板 | `BoardPanel`、侧栏 |

### 6.2 布局管理器

不要用绝对坐标（`setBounds`）堆界面；除非非常清楚限制。常用：

- **BorderLayout**：东/西/南/北/中五区，主窗口很常用。本项目主窗口：棋盘在 CENTER，侧栏在 EAST，提示在 SOUTH。
- **BoxLayout**：单方向排列，侧栏内部纵向堆叠标签。
- **GridLayout**：等大格子，操作按钮 2×3。
- **GridBagLayout**：复杂表单，登录框；可设置权重、对齐、填充。
- **空布局（null layout）**：原 Demo 里用 `setLayout(null)` + `setBounds`，适合快速演示但不适合正式项目；窗口缩放/字体变化会错位。

需要掌握：

- `pack()` 根据首选大小自动调整窗口。
- `setPreferredSize`、`setMinimumSize`、`setResizable`。
- 组件的 `preferredSize` 如何影响布局。
- `BorderFactory` 的 `EmptyBorder` / `TitledBorder` / `LineBorder`。

### 6.3 自定义绘制

`BoardPanel` 继承 `JPanel` 并重写：

```java
@Override
protected void paintComponent(Graphics graphics) {
    super.paintComponent(graphics);
    Graphics2D g = (Graphics2D) graphics.create();
    try {
        // 抗锯齿、渐变、线条、棋子、高亮
    } finally {
        g.dispose();
    }
}
```

核心 API：

- `setRenderingHint(RenderingHints.KEY_ANTIALIASING, VALUE_ANTIALIAS_ON)`：抗锯齿。
- `drawLine`、`drawRect`、`drawRoundRect`、`drawOval`、`fillOval`、`fillRect`。
- `setColor`、`setStroke`、`setFont`、`setPaint(GradientPaint)`。
- `FontMetrics`：文本宽度、ascent/descent；居中绘制。
- `AlphaComposite` 或带 alpha 的 `Color`：半透明高亮。
- `repaint()`：请求重绘；不要在 `paintComponent` 里创建大量对象或做耗时计算。
- `g.create()` / `g.dispose()`：避免修改传入 Graphics 的状态影响其他绘制。

绘制内容：

1. 背景渐变。
2. 棋盘横线、竖线、九宫斜线、楚河汉界。
3. 坐标刻度。
4. 上一步标记（起点实心点、终点橙色框）。
5. 合法落点（空位绿点、可吃子绿环）。
6. 棋子（阴影、圆形、内圈、文字）。
7. 选中圆环。

### 6.4 事件模型

必须掌握：

- **事件源**：按钮、面板、菜单项。
- **事件对象**：`MouseEvent`、`ActionEvent`。
- **监听器**：`MouseListener`、`ActionListener`。
- **适配器**：`MouseAdapter` 提供空实现，只重写需要的方法。

本项目：

```java
public class ChessController extends MouseAdapter {
    @Override
    public void mouseClicked(MouseEvent event) {
        if (!SwingUtilities.isLeftMouseButton(event)) return;
        Point p = boardPanel.getIntersectionAt(event.getX(), event.getY());
        if (p != null) handleClick(p.y, p.x);
    }
}
```

按钮/菜单：

```java
saveButton.addActionListener(event -> saveGame());
```

**EDT（事件分派线程）**：

- 所有 Swing 组件的创建和修改应在 EDT 上执行。
- 耗时任务（AI 搜索、网络、读写大文件）不要阻塞 EDT，否则界面会“假死”。
- 简单文件读写在这个规模下可以接受；若要严谨，使用 `SwingWorker`。
- 定时器使用 `javax.swing.Timer`（它的事件在 EDT 上执行），不要用 `Thread.sleep` 阻塞 EDT。

### 6.5 对话框与流程控制

- `JOptionPane.showMessageDialog`：提示。
- `showConfirmDialog`：确认（是/否）。
- `showInputDialog`：选择存档位（本例用下拉选项）。
- `JDialog` 设置 `ModalityType.APPLICATION_MODAL`：登录完成前阻止操作主窗口。
- 登录对话框通过静态 `showDialog` 封装，返回 `User` 或 `null`，调用方不需要关心内部按钮逻辑。

### 6.6 界面状态刷新

本项目把刷新集中到 `ChessFrame.refreshView()`：

- 更新当前用户/游客提示。
- 更新行棋方、将军状态、胜负/和棋。
- 更新上一步文字。
- 重建着法记录。
- 启用/禁用按钮（终局不能认输/和棋/保存；游客不能存读档）。

- 对局结束时只弹一次结果框（`announcedResult` 去重）。

好处：任何操作完成后只调用一次刷新方法，避免“某个地方改了，另一个标签忘了更新”。

### 6.7 字体与中文

- 使用 `new Font("Microsoft YaHei", ...)`；Windows 常见。即使字体缺失，Java 通常也会回退到可显示中文的字体。

- 对话框提示使用 HTML 可以换行/加粗，但要避免拼接未转义的用户输入。

### 6.8 可访问性与体验

- 按钮文字明确，禁用时配 tooltip 说明原因。

## 7. 用户系统与安全

### 7.1 需求拆解

- 注册：用户名唯一（不区分大小写即可），保存用户。
- 登录：验证用户名 + 密码；错误要提示。
- 游客：可以下棋，不能保存/读取存档。
- 持久化：关闭程序再打开，已注册用户仍可登录。
- 隔离：用户只能读写自己的存档。

### 7.2 数据模型

`User`：用户名、盐、密码哈希、是否游客。
`UserStore`：从 `users.tsv` 加载用户，注册时写回文件。
`AuthService`：负责输入校验、随机盐、哈希、登录验证。

文件格式：

```
Alice	<Base64 盐>	<Base64 哈希>
Bob	<Base64 盐>	<Base64 哈希>
```

用户名限制为 `[A-Za-z0-9_]{2,20}`，同时保证可安全用作目录名，避免 `../` 之类的路径穿越。

### 7.3 密码为什么要加盐哈希

- 不能保存明文密码：文件泄露会直接暴露密码。
- 不能只保存简单哈希：相同密码会得到相同哈希，容易被彩虹表反查。
- 加盐：每个用户一个随机 16 字节盐，`hash(salt + password)` 后再多轮哈希；相同密码也会不同。
- 比较用 `MessageDigest.isEqual`，减少基于比较时间的侧信道。
- 本项目是教学演示，使用多轮 SHA-256；生产环境应使用 **PBKDF2 / bcrypt / Argon2** 等专门算法，并设置合理成本参数。

需要掌握：

- `SecureRandom`：生成盐，不要用 `Random`。
- `MessageDigest`：SHA-256。
- `Base64`：把二进制盐/哈希转成文本存储。
- `JPasswordField.getPassword()` 返回 `char[]`；用后 `Arrays.fill(..., '\0')`。
- 输入校验：长度、字符集、确认密码一致、用户名重复。

**安全提示**：不要在日志、异常信息或界面中输出密码/哈希；不要把用户数据放到项目目录并提交到 Git。

### 7.4 持久化与文件路径

`StoragePaths.baseDir()` 默认：

```
Windows: C:\Users\<你>\.xiangqi-demo
Linux/macOS: ~/.xiangqi-demo
```

为什么用用户主目录而不是项目目录：

- 程序换工作目录后仍能找到数据。
- 不会把个人数据混进源码目录。
- 便于文档说明和清理。

可测试性：`AuthService(Path baseDir)`、`SaveManager(Path baseDir)` 可指定临时目录，避免测试污染真实数据。

### 7.5 游客

`User.guest()` 返回 `isGuest() == true` 的对象。界面：

- 保存/载入按钮禁用。
- 菜单调用时仍做防御检查并提示。
- 存档路径不会使用“游客”作为用户名（避免误建目录）。

## 8. 存档与读档系统

### 8.1 存档要包含什么

需求明确要求：棋盘局势、轮到谁、着法历史。

本 Demo 的 `GameSnapshot` 包含：

- 10×9 棋盘数组。
- `redToMove`。
- `GameStatus`。
- `endReason`。
- `List<Move>`。

写入文件的文本格式（版本化）：

```
xiangqi-save-v1
turn=red
status=ONGOING
reason=
moves=1
move=6,4,5,4,S,-
board:
r h e a g a e h r
. . . . . . . . .
. c . . . . . c .
s . s . s . s . s
. . . . . . . . .
. . . . . . . . .
S . S . S . S . S
. C . . . . . C .
. . . . . . . . .
R H E A G A E H R
```

设计要点：

- **版本行**：未来格式变化时可以识别旧存档。
- **键值行**：`turn=`、`status=`、`moves=` 容易解析和人工检查。
- **棋子矩阵**：每行 9 个 token，`.` 为空，大写红/小写黑。
- **着法行**：`move=fromRow,fromCol,toRow,toCol,棋子代码,被吃代码或-`。
- **一次只存一个对局快照**：简单、可靠。

### 8.2 写入流程

1. 验证用户、存档位（1–3）。
2. 只允许保存 `ONGOING` 的对局。
3. 生成完整文本。
4. `Files.createDirectories` 创建存档目录。
5. 先写同目录临时文件，再 `Files.move(..., REPLACE_EXISTING, ATOMIC_MOVE)`。
6. 原子移动不支持时退回普通替换。
7. `finally` 删除残留临时文件。

**为什么要临时文件 + 原子替换？** 如果直接覆盖目标文件时程序崩溃，会留下半个文件。先写临时文件再改名，读档要么看到旧版本，要么看到完整新版本。

### 8.3 读取与校验清单

读取前：

- 用户/存档位合法。
- 文件存在、大小不超过上限（例如 1 MB）。

逐项校验：

1. 文件头必须是 `xiangqi-save-v1`（允许 BOM）。
2. `turn` 只能是 `red` / `black`。
3. `status` 只能是 `ONGOING`（Demo 只支持保存进行中对局）。
4. `reason` 长度合理。
5. `moves=N` 是合法整数，范围合理。
6. 恰好有 N 条格式正确的 `move=` 行；坐标在棋盘内，棋子代码已知，被吃棋子颜色相反。
7. 下一行必须是 `board:`。
8. 棋盘恰好 10 行，每行恰好 9 个格子。
9. 每个格子是 `.` 或合法棋子字符。
10. 红黑双方各恰好一个将帅。
11. 每种棋子数量不超过上限（仕/士 2、相/象 2、马 2、车 2、炮 2、兵/卒 5）。
12. 将帅、仕/士必须在己方九宫内；象/相不能在河对岸。
13. 非行棋方不能正在被将军（否则这是上一步不可能产生的局面）。
14. 行棋方必须至少有一个合法着法（否则对局本应已结束）。
15. 棋盘行之后不能有多余内容。

全部通过后，才调用 `target.restore(snapshot)` 覆盖当前棋盘。**读档失败时当前对局保持不变。**

### 8.4 存档隔离

- 路径：`saves/<登录用户名>/slotN.txt`。
- 登录用户名来自密码验证后的 `User`，不是用户随手输入的字符串。
- 注册时限制用户名字符集，避免路径穿越。
- 游客直接禁止保存/读取。

这不是数据库级别的强安全模型，但满足“用户只能读取自己的存档”的基本要求。如果需要更强隔离，可引入数据库、加密存档、权限/会话令牌等。

### 8.5 格式方案对比

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 自定义文本 | 零依赖、可读、易校验、教学清楚 | 需要手写解析与校验 | 本项目基础 Demo |
| JSON（Jackson/Gson） | 结构清晰、生态成熟 | 增加第三方依赖、仍需业务校验 | 进阶/工程化 |
| XML | 有标准库、结构清晰 | 冗长、解析代码多 | 不推荐首选 |
| Java 序列化 | 写起来快 | 版本兼容差、安全风险高、不可读 | 不建议 |
| 数据库（SQLite） | 多用户、多存档、查询方便 | 需要 JDBC/依赖、复杂 | 大规模进阶 |

**重要**：无论哪种格式，都不能只依赖“格式解析成功”就信任数据；必须做业务校验（棋子数量、将帅位置、将军状态等）。

### 8.6 可扩展方向

- 多个存档位（本项目已 3 个）。
- 存档时间、双方用户名、对局步数、耗时。
- 自动存档（每步后写临时槽位）。
- 导出/导入 JSON 或棋谱。
- 自定义残局：允许读入任意合法局面。
- 存档加密/校验和。

### 9.5 调试技巧

- 在 `Board.tryMove` 开头打印起点、终点、当前行棋方、`isLegalMove` 结果。
- 在 `isGeneralSafe` 打印被哪一枚敌方棋子攻击（临时调试用，提交前删除）。
- 用 IDE 断点观察 `pieces` 数组：IntelliJ 的 Variables 视图可以展开二维数组。
- 写一个 `printBoard()` 临时方法，用字符画输出局面。

### 9.6 常见 bug 清单

- 行/列与 x/y 搞反。
- 马的腿算成终点方向，而不是起点方向。
- 象眼算错。
- 炮吃子忘记区分“目标为空/目标有子”。
- 兵横走判断用了目标行，导致过河前/后判断错误。
- 只检查棋子走法，不检查走完后是否送将。
- 将帅照面未处理，导致可以“对脸”。
- 移动后忘记换边，或移动失败也换边。
- 将死判断只检查“当前是否被将军”，没有检查“是否还有合法走法”。
- UI 读档后没有清除选中状态/刷新历史。
- 用户输入用 `==` 比较字符串。
- 密码明文存储/打印。
- 保存直接覆盖文件，写到一半崩溃导致存档损坏。
- 读档解析直接修改当前棋盘，失败后局面变成半成品。

## 11. 进阶功能（Task 6）及实现思路

进阶分最高 30（第 15 周）/20（第 16 周）。建议选择“能明显演示、代码可控”的 1–2 项，而不是堆很多半成品。

| 功能 | 难度 | 分值潜力 | 实现思路 |
|---|---:|---:|---|
| 合法落点高亮 | 低 | 中 | 本项目已实现：`Board.getLegalTargets` + `BoardPanel` |
| 悔棋 | 中 | 中 | 每步存 `GameSnapshot` 或 `UndoRecord`（起点、终点、被吃棋子、原行棋方）；撤销时恢复 |
| 逐着回放 | 中 | 中 | 保存快照序列；用 `javax.swing.Timer` 定时前进/后退 |
| 计时器 | 低 | 中 | 每方剩余秒数，`Swing Timer` 每秒更新；超时判负 |
| AI 对手 | 高 | 高 | 极小化极大 + Alpha-Beta 剪枝 + 局面评估；难度用搜索深度控制 |
| 走法提示 | 中 | 中 | 复用 AI 评估，给出候选最佳着法 |
| 自定义局面 | 中 | 中 | 扩展存档格式；允许编辑棋子放置；校验局面合法性 |
| 自动存档 | 低 | 低/中 | 每步后写 `autosave.txt`；启动时询问恢复 |
| 联网对战 | 高 | 高 | Socket + 协议（走子消息/心跳/认输）；线程与 EDT 交互用 `SwingUtilities.invokeLater` |
| 主题/动画/音效 | 中 | 低/中 | 渐变/图片背景；`Timer` 动画；`javax.sound.sampled` 播放音效 |
| 独立 GUI | 中/高 | 中 | JavaFX 或自绘完整界面；不得直接复用 Demo 界面 |
| 棋谱导出/导入 | 中 | 中 | 传统中文记谱或标准化坐标格式；导入需严格校验 |

### 11.1 AI 入门路线

1. **评估函数**：给棋子赋分（车 900、马 400、炮 450、兵 100、仕/相 200、将 极大值），加位置分。
2. **生成合法着法**：复用 `Board.getLegalTargets`/`isLegalMove`。
3. **极小化极大**：假设双方都走最优，红方最大化、黑方最小化。
4. **Alpha-Beta 剪枝**：减少搜索节点。
5. **难度**：简单=随机+低深度，普通=深度 2–3，困难=深度 4+，再加思考时间限制。
6. **性能**：避免在 EDT 搜索；用 `SwingWorker` 后台执行，结果回 EDT 更新界面。
7. **测试**：AI 不应走非法棋；对同一局面结果可复现（固定随机种子）。

### 11.2 悔棋实现要点

- 每次 `tryMove` 前保存快照，或记录 `UndoRecord`。
- 悔棋恢复棋子、行棋方、状态、着法历史、上一步。
- 恢复后清空选中/高亮，刷新界面。
- 与存档兼容：存档里可选择是否包含悔棋栈（通常不保存）。
- 测试：连续悔棋、吃子后悔棋、终局后是否允许悔棋。

### 11.3 计时器实现要点

- `javax.swing.Timer(1000, e -> tick())`。
- 每方独立剩余时间；换边时切换倒计时。
- 暂停/继续、超时判负。
- 必须在 EDT 更新界面，不要用后台线程直接改 Swing 组件。

### 11.4 联网对战要点

- 定义协议（例如文本行：`MOVE 6 4 5 4\n`、`RESIGN\n`、`DRAW\n`）。
- 服务端/客户端至少一方验证走法合法性，不能信任客户端。
- 网络线程收到消息后 `SwingUtilities.invokeLater` 更新界面。
- 处理断线、重连、重复消息、作弊输入。
- 工作量较大，建议基础功能稳定后再考虑。
